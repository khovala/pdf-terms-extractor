# AGENTS: правила реализации по ТЗ

Этот файл определяет, как агентам развивать проект извлечения перечней из сканированных PDF.

## 1) Цель системы

Извлекать из документов:

- сокращения;
- термины;
- определения.

И сохранять в PostgreSQL с привязкой к конкретному документу.

## 2) Источник документов

- Входная директория: `для терминов`.
- Тип файлов: PDF-сканы без текстового слоя.
- Требование: обрабатывать документы пакетно и независимо.

## 3) Обязательные свойства пайплайна

- **Надежность:** при падении/рестарте продолжать с последнего корректного состояния.
- **Идемпотентность:** не обрабатывать повторно уже завершенные документы.
- **Гибкость:** корректно работать, даже если искомые разделы отсутствуют.
- **Универсальность:** искать разделы в любой части документа.

## 4) Рекомендуемый pipeline

1. `discover` — обнаружение PDF в `для терминов`.
2. `fingerprint` — вычисление `file_hash` (SHA-256) и проверка статуса в БД.
3. `ocr` — извлечение текста и координат блоков.
4. `section-detection` — поиск кандидатов разделов по заголовкам и структуре.
5. `entity-extraction` — извлечение пар:
   - сокращение -> расшифровка;
   - термин -> определение.
6. `validation` — базовая валидация и дедупликация.
7. `persist` — запись в PostgreSQL.
8. `mark-complete` — фиксация статуса обработки документа.

## 5) Статусы обработки документа

- `NEW` — найден, но не начат.
- `PROCESSING` — в работе.
- `COMPLETED` — успешно обработан.
- `FAILED` — ошибка (с сохранением причины и шага).
- `SKIPPED` — пропущен (например, нет релевантных разделов).

## 6) Минимальная схема БД (ориентир)

- `documents(id, file_name, file_hash, status, pages_count, created_at, updated_at)`
- `extracted_items(id, document_id, item_type, term, definition, page, confidence, raw_fragment)`
- `processing_events(id, document_id, stage, level, message, created_at)`

`item_type`: `abbreviation | term_definition`

## 7) Требования к инфраструктуре

- Решение запускается в Docker (`docker-compose.yml`).
- Метаданные и результаты извлечения: **PostgreSQL**.
- OCR-движок: **Tesseract** (языки `rus+eng`).
- Для GPU-инструментов учитывать лимит 32 ГБ VRAM.
- CPU fallback должен быть предусмотрен конфигурацией.

## 8) Критерии готовности (Definition of Done)

- Документы из `для терминов` обрабатываются end-to-end.
- По имени документа можно получить все извлеченные пункты.
- Повторный запуск не дублирует обработанные документы.
- Ошибки логируются и не блокируют обработку остальных файлов.
