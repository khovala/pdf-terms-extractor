# PDF Extractor: Сокращения, Термины и Определения

Проект для обработки сканированных PDF без текстового слоя и автоматического извлечения:

- сокращений;
- терминов;
- определений.

Результаты сохраняются в PostgreSQL с привязкой к документу, чтобы получать перечни по имени файла.

## Основание

Требования из тестового задания сохранены в `Тестовое задание.md`.

## Где лежат входные документы

PDF для обработки расположены в директории `для терминов`.

## Архитектурная цель

Собрать отказоустойчивый pipeline, который:

- работает на документах разного качества;
- корректно обрабатывает отсутствие нужных разделов;
- ищет целевые разделы в любой части документа;
- умеет перезапускаться без повторной обработки уже завершенных документов;
- запускается в Docker.

## Минимальный roadmap реализации

1. OCR-слой: извлечение текста/блоков из сканов PDF.
2. Детектор разделов: поиск секций "Сокращения", "Термины и определения" по шаблонам и семантике.
3. PostgreSQL-слой: хранение документа, статуса обработки, извлеченных сущностей и их источника.
4. Restart-safe обработка: idempotent pipeline и контроль уже обработанных файлов.

## OCR

Воркер использует двухэтапное извлечение текста:

1. сначала пытается читать текстовый слой через `pypdf`;
2. если текста недостаточно, включает OCR fallback на `Tesseract` (рендер страниц через `PyMuPDF`).

Языки OCR настраиваются через `OCR_LANGUAGES` (по умолчанию `rus+eng`).

## Запуск в Docker

1. `cp .env.example .env`
2. `docker compose up --build`

После запуска:

- `postgres` доступен на `localhost:5432`
- `worker` циклически обрабатывает PDF из `для терминов`
